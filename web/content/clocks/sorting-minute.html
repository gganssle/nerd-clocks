How to read it

The centre shows hours and minutes. The seconds are the sort itself: at :00 the 96 coloured bars scatter into a random shuffle, the algorithm named in the middle works through it, and at :55 it finishes as a perfect colour wheel spiral. A white sweep then checks the result before the next minute's shuffle. The tick ring around the outside counts off the seconds too.

Bright caps flash on elements being compared; bars that turn pale are being swapped or written.

How it works

Each minute's shuffle comes from a seeded random number generator, so the same minute always produces the same puzzle. The algorithm runs instantly when the minute starts and records every compare, swap and write into a trace. The clock then replays that trace at whatever speed makes it end at :55. Selection sort needs about 4,600 steps on 96 items; radix sort needs 768.

  • Quicksort picks a pivot, partitions the rest around it, and recurses. It averages O(n log n) but can degrade to O(n²).
  • Merge sort splits the array, sorts the halves, and merges them. It is always O(n log n) and stable, meaning equal keys keep their original order.
  • Heapsort builds a max-heap inside the array, then repeatedly moves the root to the end. It is O(n log n) and needs no extra memory.
  • Shell sort does insertion sort over shrinking gaps (57, 23, 10, 4, 1), so far-away elements travel quickly.
  • Cocktail shaker, insertion and selection sort are O(n²): easy to follow, with many more steps.
  • Radix sort (LSD) never compares two elements. It deals values into buckets by one base-4 digit at a time, least significant first, relying on each pass being stable.

Why n log n is a wall

A comparison sort learns one bit per comparison. There are n! possible orderings to tell apart, so any comparison sort needs at least

log₂(n!) ≈ n log₂ n − 1.44 n comparisons

in the worst case: about 499 for these 96 bars. Radix sort gets around this bound by inspecting the digits of the keys directly instead of comparing them.

Nerd note

Real libraries use hybrids. Python's Timsort merges naturally occurring runs, and C++'s std::sort is usually introsort: quicksort that falls back to heapsort if it goes quadratic, and to insertion sort on tiny ranges.
